마산 어시장 길·구역 확장 초안 (2026-11-12)

목적
현재의 직선 골목 체험을 유지하면서 골목 약 20개를 연결할 구조를 먼저 정한다.
market-plan.json은 기획 데이터이며 아직 게임이 읽지 않는다. 교차점 위치와 업종
배치는 실제 지도·현장 사진을 대조하기 전의 초안이다.

이 자료는 업종과 분위기 참고용이다. 실제 교차점·골목 길이·현 점포 위치를
검증하는 지도 자료로 사용하지 않는다. 사용자 현장 사진은 현재 작업 폴더에 없다.

연결 구조
J01~J15는 교차점, A01~A20은 두 교차점을 잇는 골목이다. ID는 게임 내부
식별자이며 실제 골목 이름이 아니다. 모든 골목은 연결되고 여러 순환 경로가 있다.
아래 그림은 연결만 보여준다. 북쪽·해안 방향이나 실제 지도를 뜻하지 않는다.

  A13       A15       A17       A19       A20

  A14       A16       A18

시장 입구·생활, 활어·수조, 선어·해산물, 건어물·젓갈, 청과·채소,
횟집·먹거리의 여섯 구역으로 묶는다. 골목의 주 업종은 길 찾기와 분위기를
돕는 분류이며, 실제 가게는 업종을 섞어 배치할 수 있다. 길이는 현재 골목의
약 두 배인 100~140m를 작업 가정으로 둔다. 현장 검증 후 조정한다.

게임에 연결할 때의 경계
1. 길 데이터는 교차점 ID, 골목 ID, 양 끝점, 길 모양·너비, 구역 ID를 가진다.
   좌표는 실제 지도를 확인한 뒤 추가한다. 클릭 이동은 교차점 그래프에서
   경로를 찾고 현재 골목 안의 시작점과 목적지를 이어야 한다.
2. 가게 데이터는 shop ID, alley ID, 골목 내 위치, 업종, 상인 ID, 외형을 가진다.
   가게를 옮겨도 흥정·덤·구매 데이터와 저장된 장바구니는 유지한다.
3. 현재 dist/market.js의 상점·횟집 객체 계약과 dist/play.js의 거래·식사
   상태를 보존한다. dist/assets/bada-restaurant.glb는 외형 자산으로 유지한다.
4. 휴대폰에서는 현재 골목과 인접 골목을 먼저 표시하고, 먼 NPC의 동작은
   줄인다. 반복 소품은 재질·지오메트리를 공유한다. 로딩 범위는 실기기에서
   프레임 시간과 메모리를 측정한 뒤 정한다.
5. 현재 상단 구역 버튼은 임시 순간 이동이다. 골목이 연결되면 길을 따라
   걷는 이동을 기본으로 하고, 버튼은 길 찾기 또는 명시적인 빠른 이동으로
   역할을 정한다.

순서와 검증
1단계: 사용자 지도·현장 사진으로 입구, 횟집, 건어물, 청과의 상대 위치와
        실제 골목 폭·분기·막다른 길을 확인한다. 현재 시제품 좌표는 유지한다.
2단계: 새 골목 하나와 교차점 하나를 연결한다. 이동·클릭 경로·상인 탐색·
        흥정·저장·입장·착석·주문·한 점씩 먹기·복귀를 확인한다.
3단계: 구역별 대표 가게와 다른 외모·성격의 상인을 하나씩 완성한다.
4단계: 약 20개 골목으로 늘리며 모바일 프레임 시간, 초기 로드 크기,
        텍스처 메모리를 측정해 로딩 거리와 소품 밀도를 조정한다.

작업 범위
이번 단계에서는 dist 실행 코드와 GLB를 수정하지 않았다. Blender 작업자는
모델·재질 파일을, 게임 코딩 작업자는 dist 코드와 이 기획 데이터를 맡는다.
모델 외형을 바꿔도 shop ID와 놀이 저장 키(masan-play-v1)는 유지한다.
